# Decisions log

Architecture decision records for Sabiko. Each entry: the decision, the reason, and
whether it is a one-way or two-way door. Dates are when the owner settled them.

| # | Date | Decision | Why | Door |
| --- | --- | --- | --- | --- |
| 1 | 2026-10-19 | Compiler written in Rust | Repo is a Cargo project; the Rust ecosystem has the lexing/parsing crates and the Polonius reference | Two-way early, one-way after Phase 2 |
| 2 | 2026-10-19 | Target ECMA-335 CIL, minimum .NET 10 | Managed pointers cannot be generic arguments; `&T` in generic position needs `ref struct` wrappers and `allows ref struct` (.NET 9+) | One-way for emitted libraries |
| 3 | 2026-10-19 | Emit textual `.il` and assemble with `ilasm` first; direct PE writer in Phase 10 | Readable output, golden tests, fastest bring-up | Two-way (the `.il` backend is kept for tests) |
| 4 | 2026-10-19 | Borrow checking on a MIR control-flow graph, NLL-style | Same architecture as rustc; AST-level checking does not scale to flow-sensitive loans | One-way |
| 5 | 2026-10-19 | Structs are CIL value types, `StructLayout(Sequential)`; `&T` = `in T`, `&mut T` = `ref T`; structs holding references are `ref struct`s | Zero-cost, byte-identical to C#, CLR backstops escape safety | One-way for exported APIs |
| 6 | 2026-10-19 | Heap ownership via `Box<T>` over `NativeMemory`, `T: unmanaged`; GC objects only through explicit `Gc<T>` | Deterministic free; GC is opt-in for interop | One-way |
| 7 | 2026-10-19 | Strings: `&str` = `ReadOnlySpan<char>`; owned `String` is a native UTF-16 buffer; `System.String` only as `Gc<System::String>` | Keeps every struct `unmanaged`; C# passes `string` to `&str` implicitly; one copy, no transcoding, to produce a .NET string. A GC-backed `string` primitive would make most structs non-`unmanaged` | UTF-16 vs UTF-8 is one-way; decide before Phase 5 (decided: UTF-16) |
| 8 | 2026-10-19 | Naming follows .NET conventions: PascalCase for types, traits, functions, methods, fields, variants, consts; camelCase for locals and parameters. Names export exactly as written; `#[dotnet(name = "...")]` per-item override; imported .NET names kept as-is | No mangling, one name in stack traces, reflection and re-import | One-way for published APIs |
| 9 | 2026-10-19 | Source extension `.sabi`; manifest `Sabiko.toml` | Short, pronounceable, no known collisions; `.sabiko` is the fallback | Two-way until public release |
| 10 | 2026-10-19 | Dual MIT / Apache-2.0 | Mirrors the Rust ecosystem; permits adapting rustc code | One-way |
| 11 | 2026-10-19 | Traits are .NET interfaces; generics are reified with constraints; `dyn Trait` only via explicit `Gc<dyn Trait>` | Shared with C#; boxing is never implicit | One-way |
| 12 | 2026-10-19 | `Drop` lowers to `try/finally`; panics are `PanicException` | Drops run during unwinding for free; C# can catch panics | Two-way |
| 13 | 2026-10-19 | No `unsafe` in v1; pointer-touching primitives live in the C# runtime assembly | Every Sabiko-emitted assembly stays fully verifiable, so the ILVerify gate is meaningful | Two-way (can add `unsafe` later) |
| 14 | 2026-10-19 | Integer overflow: panic in debug, wrap in release; explicit `wrapping_*` / `checked_*` | Rust semantics; differs from C#'s unchecked default | Two-way |
| 15 | 2026-10-19 | Enums are tagged value types with per-variant payload fields; overlap only when all payloads are unmanaged | Correct for generic payloads; layout optimised later | Two-way until exported |
| 16 | 2026-10-19 | The HIR is the AST plus side tables keyed on `NodeId` (`ResolveResults`, `TypeckResults`) rather than a separate lowered tree | One tree to maintain; the parser's spans and node ids serve every later phase; MIR lowering reads the AST with the tables beside it | Two-way (a dedicated HIR can be introduced if the tables become unwieldy) |
| 17 | 2026-10-19 | One item namespace: a struct, function and constant may not share a name (Rust keeps separate type and value namespaces) | One name, one meaning; simpler resolution and clearer diagnostics; .NET also has one namespace per scope | Two-way |
| 18 | 2026-10-19 | `isize`/`usize` are 64-bit: Sabiko targets 64-bit .NET only | Fixed-width lets constants and literal ranges be checked at compile time; 32-bit .NET hosts are not a target | One-way for exported ABIs (struct layouts containing them) |
| 19 | 2026-10-19 | Integer literals that do not fit their type are hard errors (E0314); rustc has a deny-by-default lint | There is no `#[allow]` yet, and a silently truncated literal is never intended | Two-way |
| 20 | 2026-10-19 | No inference across function boundaries; `_` is rejected in item signatures (E0207); unsuffixed literals default to `i32`/`f64` | Matches Rust; signatures stay the documentation of a function; bodies check independently | Two-way |
| 21 | 2026-10-19 | MIR has no `Assert` terminators: overflow and division-by-zero checks are the backend's job via `add.ovf`/`div` and the CLR's exceptions | Fewer blocks and no duplicated check logic; the CLR already traps division by zero and `.ovf` opcodes trap overflow in debug builds | Two-way (rustc-style asserts can be added if a pass needs them) |
| 22 | 2026-10-19 | Semantic analysis (resolve, typeck, MIR) does not run on a file with parse errors | Recovery drops broken constructs; "cannot find value" for names defined inside them would only add noise | Two-way |
| 23 | 2026-10-19 | Loan conflicts are solved by the `polonius-engine` crate from facts generated off the MIR (origins, loans, kills, invalidations, liveness, subsets) rather than by a hand-written NLL region solver | The engine is small, well tested and is what rustc's own next borrow checker uses; our effort goes into fact generation and diagnostics, not into fixpoint machinery | Two-way (the fact generator is the interface; a different solver, or Phase 10's second checker, consumes the same facts) |
| 24 | 2026-10-19 | Move checking is a hand-written forward dataflow over the MIR; Polonius's move analysis is not used | Diagnostics need the moving statement, the later use and whether the move was partial or in a loop, which a maybe-moved lattice gives directly; the Phase 2 initialisation analysis already has the framework | Two-way |
| 25 | 2026-10-19 | A `&mut T` is implicitly reborrowed (`&mut *r`) exactly where rustc does it: at coercion sites with an expected `&mut` type (call arguments, struct literal fields, assignments, annotated `let`, `return`); an unannotated `let s = r;` moves the reference | Matches Rust, so the differential corpus and users' intuitions carry over; a `&mut` passed to two calls works, `let s = r; let t = r;` is use-after-move in both languages | Matches Rust; two-way in principle, one-way in practice (changing it would silently change which programs compile) |
| 26 | 2026-10-19 | Drop elaboration is deferred from Phase 3 to Phase 5 | No Phase 3 type has drop glue; the first droppable types (`Box`, `String`) arrive in Phase 5, and elaborating drops without a type that observes them cannot be tested | Scheduling; two-way |
| 27 | 2026-10-19 | Differential testing against `rustc` is the Phase 3 exit oracle: for every program in `tests/differential/` the two compilers must agree on accept vs borrow-error (codes and positions are not compared); any other error from either compiler fails the test | Sabiko is a syntactic subset of Rust by design (PLAN §6 item 5), so rustc is a free, independent reference implementation of the rules we claim to match; disagreement is a bug on one side or a documented divergence | Process; two-way |
