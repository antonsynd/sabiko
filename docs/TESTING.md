# Testing Sabiko

How the compiler is tested, layer by layer, and how to update each kind of expectation.
`cargo test --workspace` runs everything below except the libFuzzer targets and mutation
testing, which have their own entry points and run nightly. CI (`.github/workflows/ci.yml`)
runs the suite on Linux, macOS and Windows with the .NET 10 toolchain installed and
`SABIKO_REQUIRE_DOTNET=1`, so nothing that needs the toolchain may silently skip there, and
again on Linux with .NET 11, whose ILVerify is stricter (decision 88).

## Oracles

Sabiko is a syntactic subset of Rust, so `rustc` is a free second implementation.

- Compile-time verdicts (`crates/sabiko_driver/tests/differential.rs`): every program under
  `tests/differential/` except `run/` is compiled by both; the verdicts must agree: accept,
  or a borrow-family error. Any other error on either side fails the test. `ok_` files must
  be accepted and `err_` files rejected by both.
- Run-time behaviour (`crates/sabikoc/tests/differential_run.rs`): programs under
  `tests/differential/run/` are built as executables by both compilers (in release mode,
  wrapping arithmetic, for a program with a `//@ release` line) and run; stdout and
  exit codes must match, and when both panic so must the panic report: the message and
  the location's line and column (each compiler's file name must be its own input). An
  abort (a panic in a `drop` during unwinding, decision 56) is exit code 134 on every
  platform (`common::exit_code` maps a signal to 128 + its number and Windows' fail-fast
  statuses to 134), and the first panic's report must match then too. The
  rustc prelude is appended to the program, its lints passed as `-A` flags, so that line
  numbers agree; `Panic` is `#[track_caller]` there, so it reports its call site.
- The error conversions of `?` (`crates/sabiko_driver/tests/try_conversions.rs`, decision
  93): one function per ordered pair of a table of 38 error types, `Ok(r?)` from
  `Result<i32, FROM>` to `Result<i32, TO>`. rustc accepts exactly the pairs the test's
  `ACCEPTED` lists (checked when `rustc` runs); Sabiko must report each of those E0107 (no
  `From` yet) and every other pair E0351.
- Constant-propagation lints (`crates/sabikoc/tests/const_lints.rs`, decision 73): every
  program under `tests/differential/lints/` and `tests/ui/lints/` is built to MIR by rustc
  with `arithmetic_overflow` and `unconditional_panic` denied and compiled to IL by Sabiko;
  both must report the same lints on the same lines with the same labels. On generated
  programs (property 5 of `generated.rs`) Sabiko's lints must be a subset of rustc's.
- Generated programs (`crates/sabiko_testgen`, `crates/sabikoc/tests/generated.rs`): a
  seeded generator produces random programs in the Phase 4 subset (every integer type,
  `i128`/`u128` included) plus tuples (#6: tuple types of primitives, structs and tuples,
  wide ones past `System.ValueTuple`'s seven direct elements, as locals, parameters,
  returns and struct fields; element reads and writes; destructuring lets by value and
  through a reference) and methods (#7: impl blocks, `self`/`mut self`/`&self`/`&mut self`
  methods and associated constructors, called as `Type::Name(..)` or with method syntax on
  places, references, call results and temporaries, chained, and in the two-phase shapes
  of #15 where later arguments read the receiver or a reborrowed `&mut` argument) and drops
  (#12: half of the non-`Copy` structs implement `Drop`, printing their name and a field,
  so drop order, flags, reassignment, early exits and unwinding show in the output; no
  value is moved out of them, and `reorder` counts a statement that binds, overwrites or
  discards a value with drop glue as an effect) and enums and matching (#8: unit, tuple and
  struct variants, `Copy` enums, enums with an `impl Drop` that matches on `self`,
  fieldless ones with explicit discriminants cast with `as`, enum methods; `match` as a
  statement, `let` initialiser and inline expression, `if let`, `while let` over a state
  local, `let`-`else`, destructuring `let`s; patterns with nested variants, literals,
  ranges, or-patterns, `..`, field shorthand, `mut`/`ref`/`ref mut`/`@` bindings and
  guards, on places, references and temporaries, moving out of the scrutinee where the
  scope model allows; every `match` exhaustive by construction, with covers of variants,
  `bool` and contiguous integer ranges; the constructs it avoids carry a `TODO(#8
  follow-up)`), arrays (#9, below) and strings and range indexing (#10, below); both
  oracles above, panic locations included, are
  applied to `SABIKO_GENERATED_SEEDS` programs (a small number per CI run, thousands
  nightly), and to reorderings of them (see Properties). A failure prints the seed and the
  program; `SABIKO_GENERATED_BASE_SEED` selects the range.

  Arrays and slices (#9, `body/arrays.rs`): `[T; N]` of primitives, tuples, structs (`Copy`
  or not, with `impl Drop` or not), enums and arrays, of lengths 0 to 4 written as literals
  or `usize` constants (`[i32; LEN]`, `[u8; CAP + 1]`), as locals, struct fields, enum
  payloads, tuple elements, parameters and returns, copied and moved whole; `&[T]` and
  `&mut [T]` parameters, returns and annotated `let`s, coerced from references to arrays;
  array literals, `[]` where the type is known, `[x; N]` (a non-`Copy` operand only for N
  of 0 or 1); element reads, writes, compound assignments, borrows (`&mut a[i]`), method
  receivers and scrutinees with constant indices and with computed ones that are sometimes
  out of bounds or overflow, so rustc's `index out of bounds: the len is N but the index is
  M` is compared with its location; `.len()`; `while i < s.len()` loops. Nothing is moved
  out of an element (E0508) except by the violation knob, and a `&mut [T; N]` local coerced
  to `&mut [T]` is not treated as a two-phase reborrow (it is not one in rustc). `reorder`
  analyses indexing precisely (an index may panic unless it is a literal within an array's
  length; `&a[i]` takes `a`'s address). 2000 seeds at each of the bases 7000000, 8000000
  and 9000000 pass all five properties; the runs found four compiler bugs, fixed with
  regression programs (docs/PLAN.md, Phase 5 status). About 2.5% of borrow-clean programs
  end in an index-out-of-bounds panic, others in overflow panics of index arithmetic.

  Arrays of references (#43, decision 77, `BodyGen::ref_array_element`): a `&str` or a
  shared reference expression is now and then an element of a temporary array literal of
  them, indexed in place (`["a", s][i]`, `[&x, r][i]`) or through a range, which makes it
  a slice of references (`[a, b, c][1..][k]`), with the usual in-bounds, out-of-bounds and
  overflowing indices and ranges; the elements' loans are held while the later elements
  and the index are generated, and the expression carries them all. About a quarter of
  programs have one (`programs_use_arrays_of_references` counts them, and the ranged ones; see Coverage thresholds).
  Arrays and slices of references as locals and parameters, and tuples with references,
  are not generated yet (TODO(#92)).

  Temporary lifetime extension (#88, decision 78, `BodyGen::stmt_let_extended`): `let r =
  { &e };` (now and then in two blocks), `let r = if c { &a } else { &b };` and `let r =
  match n { 0 => &a, _ => { &b } };`, shared or `&mut`, of values of any sized type; a
  value that may be a place is borrowed as `&{ e }`, never `&(e)`, so the borrow is always
  of a temporary (only a literal or a unary operator's value is parenthesised: seed 279
  of the borrow-clean set wrote `&mut (d[i])` of an immutable `d`). The reference holds
  no loan of the scope model. About half of the programs have one
  (`programs_extend_temporaries_through_blocks_and_branches` counts each kind).

  Let chains (#86, decision 79, `BodyGen::chain_rest`): half of the `if let` statements
  and a third of the `while let` ones are chains, `if c && let p = s && d && let q = t {`:
  an optional leading `bool`, then one or two more operands, each a `bool` that prefers
  reading a binding or another `let` of any scrutinee. The later operands are generated
  with the `then` block (or loop body) already open and the earlier `let`s' bindings
  declared and locking what they borrow, as statements there are; generating an
  expression writes no lines, so the condition is still written first. `else` starts from
  the state after the whole condition (what any operand moved is moved there, as the
  borrow checker sees a failure after it), and what the scrutinee itself moved (an inline
  `match` binding the whole of a place) is moved on every path (seed 66000512).
  `programs_use_let_chains` counts the programs with a chain, one led by a `bool`, one with
  two `let`s and one with a `bool` after a `let`. Match guards are `if let <literal> =
  <place>` a sixth of the time (#98, `guard_let`), on a primitive place a guard may read,
  bindings preferred, sometimes followed by `&&` and a comparison;
  `programs_use_if_let_guards` counts the programs with one, and with `&&`.

  Aggregates of references as locals (#92, `BodyGen::stmt_ref_aggregate`): a block of its
  own declares `let a: [&T; N] = [&p, &q];` (read by index, now and then through `let s:
  &[&T] = &a[k..];`), `let t: (&T, U) = (&p, u);` (read, and destructured), or `let a:
  [&mut T; 2] = [&mut p, &mut q];` written through `*a[k] = v` (on places of two locals in
  scope, or on two `mut` locals the block declares when there are none), for primitive
  referents of a type some place in scope has. The loans end with the block, so the scope
  model only checks each borrow. `programs_use_aggregates_of_references` counts each
  form. Parameters of these types, longer-lived locals, and `&str` or
  `&&T` elements are still TODO(#92).

  Generic functions and types (#114, #115, decisions 82 and 83): half of the programs
  get helpers, one line each before the functions: `GenId<T>(x: T) -> T`, `GenPick<T>(c:
  bool, a: T, b: T) -> T`, `GenFirst<T>(x: &T) -> &T`, `enum GenOpt<T> { No, Yes(T) }`,
  `struct GenBox<T> { Value: T }` and `GenOr<T>(o: GenOpt<T>, d: T) -> T`, which matches.
  Their bodies now and then wrap a value in `GenId(e)` (with a turbofish `GenId::<T>` a
  third of the time), `GenPick(c, a, b)` or `GenOr(GenOpt::Yes(a), b)`, which evaluate
  and move both values as a tuple literal does and drop the one they do not return,
  `GenOr(GenOpt::No, b)`, or `GenBox { Value: e }.Value` (a move out of a temporary
  instance), and a shared reference to a non-array place in `GenFirst(r)` (whose `&T`
  parameter reborrows a `&mut` local) or `GenBox { Value: r }.Value` (`&*r` for a `&mut`
  local or call, which the `T` field would take as a `&mut`). A reference local
  initialised from another, `let q = r;`, is written plainly, through `GenId(r)` or
  through `GenBox { Value: r }.Value`: unannotated, that moves a `&mut` `r` (#132, decision
  92), which the scope model records (only where `r` is free, declared at this loop depth
  and not the parameter a returned reference comes from; the violation knob skips the
  check, so some programs use `r` after the move), and annotated (`let q: &mut T =
  GenId(r);`) it reborrows `r`. Each is transparent
  to the scope model; the type parameter is inferred from the context, as the wrapped
  literals are, and never as a slice (a reference to an array is not wrapped, since it may
  be coerced). The runs found two generator bugs elsewhere, in `stmt_ref_aggregate`: a
  tuple's second element was generated with the first element's shared borrow unlocked
  (seed 81000007 wrote `(&t[i], match &mut t[1] { .. })`), and so was the index read out
  of an array of references (seeds 85000088 and 86000852 moved or mutably borrowed an
  element's root there). `programs_use_generic_helpers`
  counts the programs using `GenId`, `GenId::<T>`, `GenPick`, `GenFirst`,
  `GenOr(GenOpt::Yes(..), ..)`, `GenOr(GenOpt::No, ..)` and `GenBox`.

  Traits (#116, decision 84): half of the programs, independently, get
  `program::TRAIT_HELPERS`, one line each: `trait GenKeep { fn Keep(self) -> Self; fn
  KeepRef(&self) -> &Self { self } }` with a blanket `impl<T> GenKeep for T`, `trait
  GenSign` (a required `Sign` and a provided `Twice`) for `i32` and `bool` (whose block
  overrides `Twice`), `GenKept<T: GenKeep>` and `GenSigns<T>(a, b) where T: GenSign +
  GenKeep`. Bodies wrap a value in `(e).Keep()`, `GenKeep::Keep(e)` or `GenKept(e)`, a
  shared reference to a non-array place in `(&*r).KeepRef()` (reborrowed: a `&mut` receiver
  would autoref to `&&mut T`, which rustc deref-coerces and Sabiko does not), and make an integer from
  `(e).Sign()` or `GenSigns(a, b)` of `i32` or `bool` values (cast to the integer's
  type), so method probing through a blanket impl and through two blocks, `Trait::Name`
  paths, provided methods, bounds with `where`, and an integer literal's type picked by
  the one integer block all meet rustc. `programs_use_trait_helpers` counts the programs
  using each. The runs found a borrow-checker gap older than traits: a
  `match` on a field of a moved struct read its discriminant unchecked, since only
  operands, borrows and lengths made move paths (seed 89001756; now
  `moves/err_match_on_field_of_moved_struct`). The new draws shift every program's random choices,
  which moves the other usage counts too (see Coverage thresholds).

  The `core` prelude (#13, decision 90): the programs with exactly one of the two helper
  sets (`program.prelude`, derived without a draw of its own, so the other programs keep
  their bodies) wrap a value in `Some(e).unwrap()`, `Some(e).expect("generated")`,
  `Ok::<T, u8>(e).unwrap()` or `Err::<u8, T>(e).unwrap_err()` (all `e`),
  `Some(a).unwrap_or(b)` (both evaluated and moved, `b` dropped inside the call, as
  `GenOr(GenOpt::Yes(a), b)`) or `None::<T>.unwrap_or(b)`, and a shared reference in
  `Some(r).unwrap()`, an `Option<&T>` instance (`Some(&*r)` for a `&mut` local or call,
  which `Some` would move and return as a `&mut`; the move itself is generated as `let q =
  Some(r).unwrap();`, see the reference locals above, #132). None
  of them panics. `programs_use_the_prelude` counts the programs
  with each form. With `?` (decision 93), such programs also have the helpers
  `GenTry`, `GenTryOk`, `GenTryErr` and `GenTryKeep` (`program::PRELUDE_HELPERS`, one
  `?` each, returning early or not), and wrap values in them and in the `Option`
  combinators (`or`, `and`, `xor`, `ok_or`), all transparent to the scope model
  (`BodyGen::try_value`); an element of an array of references is now and then read
  through `(*[a, b].get(i).unwrap())`, and a length through a slice method's answer
  (`(x.get(2).is_some() as usize)`, `is_empty`, `first`, `last`).
  `programs_use_try_and_slice_methods` counts them. Every harness that runs the front end itself (the MIR and IL snapshots, the layout
  test, `validate_corpus`, the generator's `reorder` and `validity`) appends the prelude
  as the driver does, through the driver's own front-end step,
  `sabiko_driver::parse_and_resolve` (which returns the user's `FileId` too). Every
  harness that compiles through the driver (UI, differential, run corpus, `no_panic`,
  generated programs) asserts that no diagnostic has all its labels in the prelude's source
  (`Compilation::diagnostics_only_in_prelude`). Compiling a program skips borrow checking and linting the prelude's bodies;
  `sabiko_driver::check_core_prelude` runs both on them, and the driver's
  `core_prelude_borrow_checks_and_lints_clean` asserts it reports nothing.

  Strings and range indexing (#10, `body/strings.rs`, `body/arrays.rs`): `&str` locals
  (a plain one lives to the end of its block, since a slice of `*s` borrows the string,
  not `s`; one carrying the loan of a `&mut self` method's result gets a region),
  parameters and returns (`fn F(s: &str) -> &str` by elision, or a literal returned from
  any single reference parameter); ASCII string literals, some with escapes (`\n`, `\t`,
  `\\`, `\"`, `\'`, `\0`, `\x41`, `\u{61}`); range places of strings, arrays and
  slices in all six forms, with constant bounds, computed ones (`(e % 4usize)..`,
  `..(s.len() - 1usize)`) and now and then bounds out of range, reversed or overflowing,
  so rustc's slicing panics are compared with their locations: borrowed (`&s[1..k]`,
  `&mut a[i..]` and writes through it), indexed (`a[1..][k] = v`, `p.A[..2][0].X += v`),
  measured (`x[a..=b].len()`), sliced again (`&s[1..][..2]`, `&"abc"[k..]`) and walked
  (`while i < a[1..].len()`); `.len()` of strings; the six comparisons of `&str`
  operands; `match` on a string (literal and or-patterns, mostly guarded bindings, a `_`
  or binding catch-all, now and then an unreachable arm) as a statement and inline, `if let` and
  `let`-`else` with literal patterns; loops walking a string by index (`&s[i..=i]`) or
  shrinking a `mut` `&str` (`t = &t[1..]`, `while let "a" | "b" = t`). A range place
  written or borrowed mutably is an `IndexMut` call that borrows its base before the
  bounds and later indices are evaluated (no two-phase borrow), so these never read the
  base, and a `&mut self` call on an element of one is not treated as two-phase. The
  left-hand side of an assignment gets its indices after the right-hand side, which Rust
  evaluates first. The constructs avoided carry TODOs: `&str` in structs,
  enums (lifetimes, Phase 9), the arrays of locals and parameters and the generator's
  tuple types (#92), comparisons of `str` places,
  non-ASCII text (decision 62), and the compiler bugs below. `reorder` treats a range
  index like a computed index (it may panic; `&a[i..]` takes `a`'s address; an
  `IndexMut` place writes its base). 2000 seeds at each of the bases 10000000, 11000000
  and 12000000 pass all five properties; about 3.5% of borrow-clean programs end in a
  slicing panic. The runs found two compiler bugs (#54), both in the drop order while unwinding,
  neither involving strings or ranges, which the generator avoids with TODOs: an operand
  with drop glue of a block's tail (`G { A: D { .. }, B: 10 / k }` after `let a = D {
  .. };`) is dropped after the block's locals instead of before them (tails with locals
  of drop glue go through a `let`), and an evaluated call or aggregate operand with drop
  glue is dropped after a later operand's statement temporary instead of before it
  (`Use(D { .. }, Get(&D { .. }, 0))`; no temporary method receiver or inline-`match`
  scrutinee has drop glue). Both are fixed (decision 71) and the TODOs removed. They
  also found three generator bugs, fixed: an
  unannotated `let v = [[], []];`, an assignment's index reading what its right-hand side
  moved, and a call's reference argument reading (in a range bound) what an earlier value
  argument moved.
- References to references (#11, `body/refs.rs`): `Ty::RefRef` covers `&&T`, `&&mut T`,
  `&mut &T` and `&mut &mut T` locals and parameters, `&&str` and `&&[T]` included, made by
  borrowing reference locals and parameters (`let rr = &r;`, `let m = &mut r;`), a borrowed
  place (`let rr = &&x;`) or by copying and reborrowing one. They are read as `**rr`, by
  auto-deref (`rr.X`, `rr[0]`, `rr.len()`), with explicit derefs (`(*rr).X`) and as `*rr`
  used as a `&T`; they are method receivers (`m.Bump(m.X)`, two-phase), `match`
  scrutinees by value (`match **rr`) and through both references (`match rr`, a
  top-level binding being the double reference), written through (`**m = v`), retargeted
  (`*m = &y;`, `*m = "lit";`) and then read, compared, and passed as arguments. A
  retarget adds the new target's loan to the retargeted local's borrows and kills the
  `&mut` doing it. Elision counts lifetimes (`Ty::lifetimes`), so only a `&self` method
  with a `&&T` parameter returns a reference (rustc's E0106 otherwise); nothing borrows a
  literal directly (no `'static` promotion, #106). About 45% of borrow-clean programs hold
  a double reference (906 of 2000 at base 5000000: 383 retarget, 70 write through `&mut
  &mut T`); `programs_use_references_to_references` counts 11 of these
  constructs. Avoided with TODOs: three levels, `&mut &T` parameters, a retarget in a
  loop of a reference declared outside it, string patterns on a `&&str` scrutinee (#58),
  double references in aggregates (#92). The two borrow-check divergences the runs found
  are fixed and no longer avoided: `&mut m` while a reborrow through `m`'s shared deref
  lives (seed 5001324, #56, decision 69) and a guard fake-borrowing a scrutinee no pattern
  reads (seed 5001979, #57, decision 65). 2000 seeds at each of the bases 4000000,
  5000000 and 6000000 pass all five properties.
- ILVerify runs on every assembly the tests produce. The only ignored error is
  `ReturnPtrToStack` (decision 30).
- The MIR validator runs after every pass in the pipeline (debug builds panic on a
  violation) and over every program in the corpus (`crates/sabiko_mir/tests/validate_corpus.rs`),
  copy forwarding included; it checks that a two-phase borrow goes into a temporary one
  call reads (`validator_rejects_misused_two_phase_borrow`). The borrow checker's
  two-phase rules (#15) also have hand-built MIR tests in
  `crates/sabiko_borrowck/tests/loans.rs`, one per rule: reads and shared borrows during
  the reservation, explicit borrows, writes, moves and second reservations, the conflict at
  activation, shared borrows taken before the reservation, reservations across blocks, the
  loan after its activation and a two-phase borrow nothing activates. Copy forwarding
  (`sabiko_mir::forward`) also has hand-built MIR unit tests, one per condition, each a
  body where breaking the condition would change the value read; the run-time differential corpus (`regressions/stack_values.sabi`,
  `regressions/operand_order_sibling_call.sabi` among others) and the generated programs
  check the optimised code against rustc.

## Coverage thresholds

The `programs_*` tests of `crates/sabiko_testgen/tests/validity.rs` count, over seeds 1 to
500, how many generated programs have each construct, and fail when a count falls under
its threshold: a construct that silently stopped being generated. Every count goes
through `coverage()`, which prints `coverage <test>: <name> = <count> (min <threshold>)`.
The thresholds are measured, not picked: `python3 scripts/measure_coverage.py` counts over
the 10 windows of 500 seeds from 1 to 5000 (`SABIKO_COVERAGE_BASE_SEED` moves the window,
`SABIKO_COVERAGE_MEASURE` turns the assertions off) and each threshold is 75% of the
smallest window's count, rounded down, at least 1 (a count that is 0 in some window
fails the script instead: that construct is barely generated). The margin lets a threshold survive the
reshuffle any change to the generator's draws makes, since the test only counts one
window; re-measure and update after a generator change that moves the counts. Measured on
2026-11-11, after #49, #13's first part and #132:

| test | count | min | mean | max | threshold |
| --- | --- | --- | --- | --- | --- |
| extended_temporaries | extend through a block | 85 | 103.3 | 115 | 63 |
| extended_temporaries | through an `if` | 84 | 104.3 | 117 | 63 |
| extended_temporaries | through a `match` | 46 | 53.8 | 63 | 34 |
| unreachable_patterns | unreachable pattern (default and borrow-clean) | 104 | 128.2 | 145 | 78 |
| mut_ref_locals_to_type_parameters | moved into a type parameter | 6 | 7.1 | 9 | 4 |
| mut_ref_locals_to_type_parameters | reborrowed through an annotated `GenId` | 4 | 6.7 | 9 | 3 |
| 128_bit_integers | i128 | 352 | 379.6 | 395 | 264 |

## Properties

- Parser: `parse(pretty(parse(s)))` round-trips; the parser never panics on arbitrary text
  or token soup (`crates/sabiko_parser/tests`, proptest). The round-trip generator covers
  the #8 syntax too: enums (unit, tuple and struct variants, documented fields,
  discriminants), every pattern kind in every position (`let`, parameters, arms, `if let`,
  `while let`, `let`-`else`), and `match` with guards. Extending it found a printer that
  dropped the doc comments of variant fields, `_ if break => ..` rejected (`break` took `=>`
  for its operand) and arm bodies such as `if c {} else {}[i]` printed without the
  parentheses that keep a block-like expression from ending the arm
  (`match_and_enum_syntax_roundtrips`); `pub` on a variant field is now rejected, as rustc
  does (`tests/ui/parse/variant_field_visibility.sabi`).
- Whole pipeline never panics on arbitrary text, token soup, or random mutations of every
  corpus program; accepted programs produce non-empty IL; the two runs per input (to MIR
  and to IL) report identical diagnostics, in the same order, up to code generation
  (`crates/sabiko_driver/tests/no_panic.rs`, proptest; `PROPTEST_CASES` scales it).
- Determinism and idempotence: compiling a generated program twice gives identical
  diagnostics, MIR and IL; inserting no-op statements at random statement boundaries leaves
  the verdict and error codes unchanged (`crates/sabikoc/tests/generated.rs`).
- Reordering: swapping adjacent independent statements of a generated program leaves
  Sabiko's verdict and error codes unchanged (`sabiko_testgen::reorder`; independent means
  disjoint locals, no control flow, at most one statement that prints, calls or may panic,
  and no write to memory a reference may alias next to any other access to it). The
  analysis is not trusted: rustc's verdict on the reordered program must equal Sabiko's,
  and a reordered borrow-clean program must run exactly as the original does under rustc,
  and as rustc does under Sabiko. Weakening the analysis on purpose is caught: without the
  aliasing rule 5 of 2000 seeds change Sabiko's verdict, without the one-effect rule 11 of
  60 borrow-clean seeds change rustc's output.
- Constant-propagation lints on generated programs (decision 73): rustc builds each
  borrow-clean program to MIR with `arithmetic_overflow` and `unconditional_panic` denied;
  every E0600/E0601 Sabiko reports must be one of rustc's, on the same line with the same
  label. The comparison drove the lint's design: over 10000 seeds at four bases it found
  the cases where Sabiko's MIR walks differently from rustc's (`if` conditions lowered as a
  `bool` temporary, repeated match tests, the order of a literal test's edges, a `let`
  ranges `4..=4` tested twice, promoted borrows, enum casts with explicit discriminants,
  drops elaborated away); after them Sabiko reports no lint rustc does not and misses at
  least one of rustc's in 34 of the 10000 programs. The other generated properties allow
  both lints on both sides (`-A`), so overflowing constants still compile and panic.

What the pass found, for calibration: fuzzing found three crashes in MIR building on
`!`-typed expressions (`*never`, `never.Field`, `if loop {} {}`); the generator found a
miscompile (a place operand read after a later argument mutated it), an `ilasm` syntax error
(`stind.u1`), three false borrow-checker rejections with the same root cause (lazy operand
reads), and a float formatting tie rounded the wrong way in the runtime. The hand-written
corpora had caught none of them. Each has a regression program under
`tests/differential/run/regressions` or `tests/ui`.

The first nightly run (2026-10-20) added two fuzz crashes: the pretty printer glued a
malformed attribute's arguments to its path (`#[d s {)]` printed as `#[ds {)]`; attributes
now follow Rust's grammar), and constant evaluation panicked on a shift of a constant whose
declared type did not resolve. The tests written to kill the type checker's surviving
mutants then found three more: `f32` constants were computed in f64 without rounding (a
miscompile), a cast gave its type to any integer variable rather than only to a literal
operand (`let t = 300; t as u8` was rejected), and `<<=`/`>>=` accepted float operands.

The second nightly run (2026-10-21) found two more. Both pipeline fuzz targets hit a MIR
validation panic on the borrow of a diverging operand (`&break 4;` in a loop, `let q =

to the destination (`tests/ui/borrowck/ok_never_borrow.sabi`,
`tests/differential/run/regressions/borrow_of_diverging.sabi`). The parser round-trip
property found a struct literal in the block of an `if` nested in a `while` condition
rejected (`while if c { let _ = A {}; } {}`): the condition's struct-literal restriction
reached the block, where rustc lifts it at every brace
(`tests/ui/parse/ok_struct_literal_in_condition_block.sabi` and a proptest seed).

The fourth nightly run (2026-10-25) overflowed the parser's stack with ~1900 nested blocks:
nothing limited nesting, and every stage recurses over the tree. The parser now stops at 256
levels (E0109) and `crates/sabiko_driver/tests/nesting.rs` checks each kind of nesting at
the limit, through code generation, and one level past it. Its slow units (deeply nested
`&`) exposed type resolution quartic in the depth of a type.

Adding the statement-reordering property (2026-10-29) and running the generated programs
from a new base seed (100000) found a false rejection: a `&mut T` place passed where a `&T`
is expected was reborrowed mutably, so `Weigh(&*tmp, m, tmp)` was E0408 where rustc
accepts it. Coercion sites now reborrow with the target's mutability
(`tests/differential/loans/ok_coerce_mut_to_shared.sabi`,
`tests/differential/run/regressions/coerce_mut_to_shared.sabi`, the `coercions` MIR
snapshot).

Running 2000 generated seeds from three bases (1, 500000, 9000000) on the IL-shaping work of

took the topmost value waiting on the evaluation stack could then take one below it, so
`-1.5 - cur` computed `cur - -1.5` (seed 9000542 lost a panic, seed 501144 failed

Extending the generator to enums and matching (#8, 2026-11-05) found six bugs that the
corpora had missed: two false E0500s for a guard on a match through a reference (the
fake borrow's `&&T` temporary, and a guard reading a binding of the whole `&T`

of a whole `&mut` scrutinee stays E0500 (`&&mut T`, a known gap the generator avoids).
Borrow checking of code that patterns make unreachable (rustc checks a later arm and the
`else` of an irrefutable `if let`, Sabiko did not; seeds 2001893 and 3000551) was a gap
the generator avoided by making no pattern unreachable until #47 added false edges

checks that a fair share of programs have one. Also,
the reorder analysis learnt that a `ref` binding takes its scrutinee's address (seed
1000244).

## Fuzzing

`fuzz/` holds libFuzzer targets (nightly Rust): `parse` (parser plus pretty-printer
fixpoint), `pipeline` (the whole pipeline through IL on arbitrary text) and
`pipeline_structured` (token soup built with `arbitrary`). `scripts/fuzz.sh <target>
<seconds>` seeds the corpus from every `.sabi` in the repository and runs the target for a
budget; the nightly workflow runs each target and uploads any crash as an artifact. A crash
is a compiler bug: minimise it, add the input as a UI or no-panic regression test, fix.

Setup: `rustup toolchain install nightly --profile minimal && cargo install cargo-fuzz
--locked`. The script puts the nightly toolchain's own `bin/` (`rustup which --toolchain
nightly cargo`) first on `PATH` rather than calling `cargo +nightly`: `+toolchain` only
works when the `cargo` first on `PATH` is rustup's proxy, and with Homebrew's `rust` formula
(or a distro Rust) ahead of it `cargo +nightly` fails with "no such command: `+nightly`".
`rustup run nightly cargo fuzz` is not enough either, because cargo-fuzz runs `cargo build`
through `PATH` and finds the Homebrew cargo again, which rejects the `-Z` flags. The same
shadowing makes plain `cargo` ignore `rust-toolchain.toml`; on Homebrew, putting
`/opt/homebrew/opt/rustup/bin` first on `PATH` in the shell profile fixes it for every
command.

## Mutation testing

`scripts/mutants.sh [--shard k/n] [crate...]` runs `cargo mutants` (configuration in
`.cargo/mutants.toml`) on `sabiko_borrowck`, `sabiko_codegen` and `sabiko_types`, testing
each mutant with the suites that exercise the crate, and fails when a crate's score drops
below its threshold. Scores and the list of known equivalent mutants are recorded below;
the nightly workflow runs it and uploads `mutants.out`.

Setup: `cargo install cargo-mutants --locked`, then `source tools/env.sh` and export
`SABIKO_REQUIRE_DOTNET=1` so the .NET suites fail rather than skip (a skipped suite lowers
the `sabiko_codegen` score). The script runs on macOS's stock bash 3.2 and, when rustup is
installed, puts the pinned toolchain's `bin/` first on `PATH`, so a Homebrew `cargo` does
not replace the pinned toolchain for the builds and tests cargo-mutants runs. It mutates sources in place for hours: do not
edit or build in `crates/` while it runs, and run fuzzing from a separate `git worktree`.

Each mutant's tests get an explicit `--timeout` (300 seconds, `test_timeout` in the script;
`MUTANTS_TEST_TIMEOUT` overrides it). cargo-mutants' own limit scales its baseline test run,
and that run tests only the mutated package, not the `--test-package` suites. Before
nightly run 18 (2026-11-06) the nightly runs used that limit: the `sabiko_codegen`
baseline took 9 seconds, so the limit was the 60-second floor of `.cargo/mutants.toml`,
while a mutant's full suite takes over a minute (`differential_run` alone takes 30
seconds). The 44 codegen "timeouts" of run 18 were mutants that the fast tests did not
kill: 37 were cut off in `generated`, before `interop` and `run_pass` ran, and 7 hung in
`layout`. A timeout counts as caught, so a real survivor among them would have been
counted as killed. Applied by hand, the one checked (`||` as `&&` in `payload_type_name`)
is killed by `interop`. The nightly workflow runs each crate as round-robin shards
(`scripts/mutants.sh --shard k/n <crate>`, one runner each, no verdict per shard): four
for `sabiko_borrowck` and `sabiko_codegen`, eight for `sabiko_types` since run 25
(2026-11-10), when its 1786 mutants took up to 2h18m per shard of four and one shard ran
into the 150-minute job limit (#125). A `mutants-score` job then judges each crate on the
counts of all its shards' `mutants.out` directories (`scripts/mutants.sh --score <crate>
--shards n <dir>...`) and fails when a shard's results are missing. The longer timeout let three codegen mutants exhaust a
runner's memory (run 19): `next += 1` as `next *= 1` in the worklist loops of
`drop_glues`, `inline_array_structs` and `byref_tuple_structs` never advances, so the

Shard 0 lost its runner ("received a shutdown signal") about two hours in, as in run 24.
The 62 mutants it had not finished were run locally with the same suites and a 10 GB
address-space cap. None failed an allocation, timed out or took more than 54 seconds, so
no single mutant explains the lost runner and nothing is excluded for it. Shards 1–3
measured 1113 caught, 97 missed and 5 timeouts of 1215 viable: 92.0%. Most of the
survivors were in the trait code, whose run-time programs only `sabikoc`'s suites build,
and `sabikoc` is not among this crate's test packages. So `sabiko_driver`'s `run_corpus`
test now compiles every run-time program (`tests/differential/run`, `tests/run-pass`) to
IL in process, in about 4 seconds. That and new fixtures kill 56 of the 97, each checked by
applying the mutant by hand, then confirmed by re-running all 97 with `cargo mutants --re`:

- `ui/typeck/trait_impl_shapes`: overlap and selection over arrays, structs and a
  repeated parameter (`unify`'s and `match_ty`'s arms and operators, `walk`), a blanket
  block after a specific one (`unify`'s right-hand parameter), and types holding an error
  that implement everything (`has_error`'s tuple and struct arms).
- `differential/traits/ok_selection_rounds`: selection that needs a second round
  (`known_nodes` as 0 or 1 and its compound arms, `select_obligations`).
  `ok_selection_by_shape`: one block chosen by a literal's shape (`could_be`), and
  `clone` through `&mut [_; 2]` (`may_be_copy_like`'s `&mut` arm).
- `differential/run/traits/shared_item_names` and the MIR fixture `trait_item_paths`:
  items of two traits with the same names (`select_trait_item`, `may_implement`'s `> 0`,
  `check_fn_path`'s and `check_trait_const_path`'s `chosen != def`), and trait constants
  as range bounds. With `PatValues::value`'s `is_assoc_const` guard as `false`, that
  function lost its body with no diagnostic.
- `ui/typeck/turbofish_and_unknown_methods`: a turbofish on a variant, an associated
  function and a method (`check_call`'s path arm, `instantiate`'s segment filter,
  `check_method_call`), and `unknown_method`'s wording for enums and type parameters.
- `ui/typeck/trait_impl_recovery`: impl bounds on the trait's parameter or another
  (`check_impl_types`), an associated constant of an unknown type (`check_impl_const`),
  and a wrong-arity instance passed on (`adt_type`'s guard; field access cannot tell,
  since `field_ty` re-checks the arity).
- `[Self; 2]` in `ui/typeck/trait_self_sized` (`holds_by_value`), the MIR fixture
  `drop_generic_instances` (`structs_needing_drop`'s probe), a parameter used only inside
  an array or tuple field (`Ty::mentions`), and an `infer.rs` unit test of the occurs
  check inside instances (`occurs`, `is_cyclic`). `ItemTypes::impl_def` had no callers
  and is gone.

That leaves 41 of 1215 (96.6%): the 21 equivalent or older survivors listed above for
run 23, 16 new equivalent mutants, and 4 not yet killed. Equivalent:

- No trait `impl` block is for a type holding a reference or for an unsized type: such a
  block is E0107 and `check_impl_type` does not register it. So `unify`'s, `match_ty`'s and
  `could_be`'s `Ref` and `Slice` arms were dead, and their mutants (`unify`'s `Ref` arm
  deleted, and its `&&` as `||`, its `Slice` arm deleted, the `Ref` `&&` as `||` of the
  other two) equivalent. The arms are removed, with a note that they come back with such
  blocks.
- The patterns that `unify` and `walk` see hold only the two blocks' own parameters, all
  in `vars`, and the substitution holds only those. So `unify`'s two `vars.contains`
  guards (left-hand `p`, right-hand `q`) and `walk`'s guard as `true` change nothing.
- `may_be_copy_like`'s `Infer` and `Array` arms deleted: the fall-through asks
  `implements`, which answers "ambiguous" for any type with inference variables, the
  same `true`.
- `adt_args`' `*d == adt && args.len() == generics.len()` as `||`: when `Self` names a
  struct or enum in its trait block, both operands always hold.
- `builtin_impl`'s `depth + 1` as `depth * 1`: the built-in `Copy`/`Clone` recursion
  follows a finite type and ends anyway; only bounds on blocks can recurse without end.
- `Ty::is_copy` as `false` and its `!` deleted: it is only the fallback for when no `Copy`
  language item exists, and the resolver always defines one (decision 86). `Ty::subst`'s
  `||` as `&&` only skips a fast path.
- `PatValues::value`'s `is_assoc_const` guard as `true`: a plain constant evaluated
  through `trait_const` gives the same value (the IL is identical). `field_defs`'
  substituted field type deleted: exhaustiveness takes column types from the place being
  matched, and a wild sub-pattern's type is only checked for errors.

Not killed, and not shown equivalent: `known_nodes`' three `+` as `*` (a variable bound to
a blanket block's compound of fresh variables, `(?f, ?f)`, would not count as progress,
but no program found needs the extra round), and `implements_at`'s `depth > DEPTH_LIMIT`
as `==` (a bound chain 64 levels deep). With about 1620 viable mutants and 37 equivalent
ones, 98% was out of reach for `sabiko_types` whatever the tests.

So the equivalent `sabiko_types` mutants are now excluded in `.cargo/mutants.toml`
instead of counted (#125); the threshold stays at 98. Five of the 37 are gone with the
dead `Ref`/`Slice` arms above. One more appeared: `unify`'s right-hand guard as `true`,
whose run-25 result was in the lost shard 0. 32 are excluded. Each pattern names the
file and the mutation, not the line, so it survives edits elsewhere. Where an equivalent
mutant read exactly like a killable one, the code tells them apart: `unify`'s
right-hand binding is `q`, the tuple-struct arm of `check_pat_in_mode` binds `ctor`, and
`binary`'s `(max << 1) | 1` and `cast`'s float guard are matched by column, unique in
those functions. `cargo mutants --list -p sabiko_types` with and without the patterns
differs in exactly those 32; check that again when changing them. A pattern that stops
matching only brings its mutant back as a survivor. `field_defs`' "delete field ty"
stays counted: cargo-mutants 27.1 does not apply `exclude_re` to struct-field deletions.
Shard 0's other survivors are unknown until a nightly scores all eight shards.

## Interop

`tests/interop/<name>/` checks what C# sees of a Sabiko library
(`crates/sabikoc/tests/interop.rs`). Each case is `lib.sabi`, `Test.cs` and
`expected.stdout`: the harness compiles `lib.sabi` with `sabikoc --emit=dll` and verifies
it with ILVerify, checks that it is valid Rust when rustc is installed (with the builtins
as a prelude), compiles `Test.cs` with the Roslyn `csc` from `tools/csc` (run on `dotnet`,
no SDK: `-nostdlib` against `tools/ref/*.dll`, `lib.dll` and `Sabiko.Runtime.dll`, the way
`scripts/build-runtime.sh` builds the runtime, with `-warnaserror`), writes the same
`runtimeconfig.json` as `sabikoc --emit=exe`, runs it, and requires exit code 0, an empty
stderr and stdout equal to `expected.stdout` (`BLESS=1 cargo test -p sabikoc --test
interop` writes it; review the diff). A C# program checks what it can itself and exits
with 1 on a mismatch; the expected output pins the rest, such as Sabiko's `Print` output
interleaved with C#'s. `enum_layout` (Phase 5) reads the enum layout by reflection, builds
enums field by field (tags, `Tag_`, payload types `<Variant>Payload`, an `int64` tag),
passes them by value, `in` and `ref`, reads what Sabiko returns, compares a C# `switch` on
the tags with Sabiko's `match`, passes a struct the same three ways, and catches the
`PanicException` of a `match` on a tag no variant has. Its first run found two interop
bugs (decision 59): C# could not read payloads (a nested type and a field of one name are
ambiguous in C#) nor call any function with an `&T` parameter (`modreq(InAttribute)` on a
static method's parameter is CS0570). `array_spans` (#9, decision 61) passes C# arrays,
array slices and a `stackalloc` span to `&[i32]` (`ReadOnlySpan<int>`) and `&mut [i32]`
(`Span<int>`) parameters, holds a `ref readonly int` that a Sabiko function returns into
the C# array, indexes the inline arrays Sabiko returns (C# 12 inline-array indexing) and
one in a struct field, passes an array by `ref` and `in`, and catches the panic of an
out-of-bounds index; it passed on its first run. `ref_wrappers` (#11, decision 64) builds
the module's `Ref<int>`, `Ref<Ref<long>>` and `RefMut<int>` over C# locals and passes them
to `&&i32`, `&&&i64` and `&mut &mut i32` parameters (`in` and `ref`). Its first run found
that C# cannot read a wrapper's `Value` (CS0570: a `ref` field whose type parameter allows
`ref struct`s), which the decision records.

## Dependencies

`cargo deny check` (`deny.toml`; setup: `cargo install cargo-deny --locked --version
0.20.2`) checks the dependency graph: every crate's licence must be on the allow list (MIT,
Apache-2.0 and Unicode-3.0 today; an `OR` expression passes when one alternative is
allowed, so copyleft alternatives are never chosen), every crate must come from crates.io,
and two versions of one crate are reported as a warning. CI runs `cargo deny check licenses
bans sources` on Linux on every push (the graph does not depend on the platform); the
nightly workflow runs `cargo deny check advisories` against the RustSec database, so a new
advisory is reported without failing unrelated pull requests (decision 45). The `fuzz/`
workspace is not checked: it is built only by the nightly fuzzing job and never
distributed.

## Benchmarks

`benchmarks/` compares the runtime and memory of Sabiko-compiled programs with the same
programs written in C# (and built by rustc, for reference); `benchmarks/README.md` has the
details and decision 50 the methodology. Each benchmark is a `bench.sabi` and a `bench.cs`
with the same algorithm and output. `benchmarks/run_benchmarks.py` (Python standard library
only) builds both in two configurations (Sabiko `--release` vs C# `-optimize+`, the
headline; Sabiko debug vs C# `-checked+`), checks that every language prints the same
output, and measures two modes: whole-process launches (wall time and peak RSS, 5 warmup +
100 timed, round-robin across languages) and in-process steady state through a C# host
(`benchmarks/host/BenchHost.cs`: time and exact allocated bytes per iteration, GC counts;
20 warmup + 100 measured). It reports n, mean, stdev, min, p50, p90, p99 and max per metric
and the Sabiko/C# ratios as a table, `--json` and `--markdown`.

The nightly workflow runs the whole set (about 17 minutes including setup), puts the report
in the job summary and uploads the JSON. Time is never gated (shared runners are noisy);
allocations are: `benchmarks/allocation_gate.py check` fails when a Sabiko benchmark
allocates more than 10% over `benchmarks/allocation-baseline.json`, which changes only
through `allocation_gate.py update` and a reviewed diff. CI runs the harness's unit tests
(`python3 -m unittest discover -s benchmarks -p 'test_*.py'`) and a `--smoke` run of one
benchmark on Linux. `benchmarks/results/latest.md` is an example report from a local run,
labelled with its machine. On Mondays the nightly job also commits its p50s to `benchmarks/results/history.json` and a chart of the Sabiko/C# ratios
over time to `benchmarks/results/trend.svg` (`benchmarks/trend.py`, decision 68).

## Adding a test

Every fixed bug adds a test in the matching layer: a UI fixture for a diagnostic, a
run-pass or differential program for behaviour (differential when the program is valid
Rust, which it almost always is), a hand-built MIR test for a borrow-checker rule, an IL
fixture for instruction selection. Programs in `tests/differential/` must stay valid Rust:
the harness prepends `#![allow(nonstandard_style, unused, dead_code)]` and definitions of
`Print`, `PrintLine` and `Panic`, so the corpus must not define those names.
